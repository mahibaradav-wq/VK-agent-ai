## Цель

Не терять AI unit, когда провайдер уже вернул успешный HTTP-ответ на платный POST, а приложение не смогло прочитать или обработать тело ответа.

## Политика списания

| Ситуация | units |
|----------|-------|
| Доказано, что запрос не ушёл (DNS, ECONNREFUSED и т. п. до соединения) | 0 |
| Неопределённый результат POST (таймаут, abort, reset, `fetch failed`) | 1 |
| Получен любой HTTP-ответ AI API (2xx/4xx/5xx) | 1 |
| Любая ошибка обработки ответа после HTTP 2xx | 1 |
| Ошибка скачивания файла по URL после 2xx | 1 за исходную генерацию; скачивание unit не добавляет |
| Успех | 1 за каждый платный вызов (пост с revise = 2) |

## Аудит учёта (блок D)

- `paidCallsFromResult` / `paidCallsFromError`: принимают только целые ≥ 0, иначе fallback 1 / 0. Теперь все ошибки провайдера после HTTP-ответа несут `paidCalls`, поэтому значение 0 приходит только при доказанном pre-send.
- `attachPaidCalls`: перезаписывает свойство, а не прибавляет. Повторное оборачивание не создаёт двойного списания.
- `callWithFallback`: перед каждым провайдером, включая fallback, вызывается `ensureReserve`. Расход неудачной попытки сразу проводится через `notePaidCalls`, итоговая ошибка несёт сумму всех неудачных попыток. Внешний `catch` сервиса добирает разницу, только если `paidCalls` ошибки больше уже учтённого `charged`, поэтому двойного учёта нет.
- `notePaidCalls`: сначала `charged += calls`, потом попытка увеличить резерв. Если лимит не пускает, `charged` остаётся честным.
- `settlePaidAi`: исправлены дефекты 12 и 13.
- `ensureReserve`: не менялся. Если резерв нельзя увеличить, новый платный запрос не отправляется (проверено тестом по числу вызовов fetch).

Итог: в нормальном потоке used не превышает лимит, потому что каждая попытка заранее резервируется. В аварийном случае `charged > reserved` подтверждённые платные вызовы не теряются: used может стать больше лимита ровно на уже потраченные units, это пишется в аудит, и следующий запрос отклоняется до отправки.

## Двойное списание и потери

- Двойного списания нет: `attachPaidCalls` перезаписывает значение; сервис добирает только разницу сверх `charged`; скачивание по URL не тарифицируется; повторный `settlePaidAi` идемпотентен.
- Подтверждённые платные вызовы не теряются: любая ошибка после HTTP-ответа несёт 1; revise учитывается при ошибке разбора; overage записывается, а не обрезается.

## Оставшиеся ограничения

- Если провайдер сообщит больше вызовов, чем зарезервировано, а лимит исчерпан, used честно превысит лимит на уже потраченные units (аудит `AI_USAGE_OVERAGE`). Сама генерация в этом случае завершается ошибкой лимита, хотя ответ был получен: так было и раньше.
- Ошибка скачивания по URL трактуется как потеря уже оплаченной генерации (1 unit), повторной загрузки нет.
- Всё проверено только через fake fetch и тестовую БД; реальный провайдер не вызывался.
