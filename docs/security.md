# Обзор безопасности Polka Social

Документ этапа 14. Это разбор фактических границ текущей реализации, а не сертификат соответствия.

## Что проверяется на сервере

- Доступ к `/app` и `/admin` требует сессии Auth.js.
- Права workspace проверяются в сервисах, а не только в UI. Чужой `workspaceId` / `projectId` / `postId` отклоняется.
- Платформенная админка использует `PlatformAdmin`. Роль Owner в workspace сюда не пускает.
- Токены соцаккаунтов шифруются AES-256-GCM отдельным `TOKEN_ENCRYPTION_KEY`; в production он обязателен и не должен совпадать с `AUTH_SECRET`.
- Для бесшовного перехода старые токены, зашифрованные прежним fallback `AUTH_SECRET`, остаются доступны только на расшифровку. Новые токены шифруются выделенным ключом.
- Пароли Telegram/VK не принимаются.
- Коммерческий биллинг из рабочего приложения исключён: `/api/subscription` и `/api/webhooks/billing` отвечают 410, `BILLING_CHECKOUT_ENABLED` ничего не включает.
- AI-ключи, S3 и почтовый провайдер остаются на сервере. Без credentials адаптер не имитирует успех.

## Что добавлено на этапе 14

- Заголовки: `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, CSP.
- `robots.txt` закрывает `/app`, `/admin`, `/dev`, `/api`.
- Старт процесса проверяет, что `AUTH_SECRET` не короче 32 символов и не является заглушкой.
- Формы входа, регистрации, сброса пароля и контактов ограничивают частоту запросов по IP. Caddy перезаписывает `X-Real-IP` адресом TCP-клиента; приложение не доверяет пользовательскому `X-Forwarded-For`. Локальный Map-лимитер действует в одном процессе Node и не является распределённой защитой.
- `/api/health` отвечает `{ ok, db }` и не печатает connection string.
- Локальный почтовый стенд не упоминает имена секретов на странице.
- Публичная регистрация закрыта, пока `AUTH_ALLOW_PUBLIC_REGISTRATION` не равен `true`. Первый владелец на пустой БД и email с действующим приглашением регистрируются. Существующие пользователи входят как раньше.
- Платные вызовы OpenAI и чтение баланса ChatGPT выключены, пока `AI_LIVE_ENABLED` не равен `true`. Счётчик `DEFAULT_MONTHLY_LIMIT=0` сам по себе безлимитен и не заменяет бюджет.

## Остаточный риск

- CSP разрешает `'unsafe-inline'` и `'unsafe-eval'`: так работает гидратация Next.js. Это не замена nonce-CSP. Приоритет: оставить как есть до внедрения nonce/strict-dynamic без поломки App Router; не ослаблять `connect-src`.
- 2FA/TOTP нет. Для личного кабинета приоритет ниже закрытой регистрации, отдельного `TOKEN_ENCRYPTION_KEY` и выключенного mailbox; внедрение потребует миграции и восстановления доступа.
- HSTS нужно включать на HTTPS-прокси, не в локальном `npm start` по HTTP.
- Rate limit хранится в памяти процесса. Несколько инстансов не делят счётчик. Платный Redis не обязателен: для личного кабинета достаточно одного процесса Node; следующий бесплатный шаг — таблица в PostgreSQL с TTL, не внешний WAF.
- `AUTH_DEV_MAILBOX=true` в настоящем production откроет `/dev/mailbox`. В проде флаг должен быть выключен, а письма идут только через HTTP-адаптер.
- In-memory rate limit и health не заменяют WAF, backup и мониторинг инцидентов.

## Секреты

Не коммитить `.env`. В репозитории только `.env.example` с заглушками. Страницы и JSON админки не должны содержать `AUTH_SECRET`, пароль БД, `sk-`, `whsec_`, `Bearer` и ключи провайдеров. Проверка: `npm test` и `npm run test:e2e`.
