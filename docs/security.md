# Обзор безопасности Polka Social

Документ этапа 14. Это разбор фактических границ текущей реализации, а не сертификат соответствия.

## Что проверяется на сервере

- Доступ к `/app` и `/admin` требует сессии Auth.js.
- Права workspace проверяются в сервисах, а не только в UI. Чужой `workspaceId` / `projectId` / `postId` отклоняется.
- Платформенная админка использует `PlatformAdmin`. Роль Owner в workspace сюда не пускает.
- Токены соцаккаунтов шифруются AES-256-GCM. Пароли Telegram/VK не принимаются.
- Billing webhook проверяет HMAC. Redirect после checkout не ставит статус «оплачено».
- AI-ключи, S3 и почтовый провайдер остаются на сервере. Без credentials адаптер не имитирует успех.

## Что добавлено на этапе 14

- Заголовки: `X-Frame-Options: DENY`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, CSP.
- `robots.txt` закрывает `/app`, `/admin`, `/dev`, `/api`.
- Старт процесса проверяет, что `AUTH_SECRET` не короче 32 символов и не является заглушкой.
- Формы входа, регистрации, сброса пароля и контактов ограничивают частоту запросов по IP.
- `/api/health` отвечает `{ ok, db }` и не печатает connection string.
- Локальный почтовый стенд не упоминает имена секретов на странице.

## Остаточный риск

- CSP разрешает `'unsafe-inline'` и `'unsafe-eval'`: так работает гидратация Next.js. Это не замена nonce-CSP.
- HSTS нужно включать на HTTPS-прокси, не в локальном `npm start` по HTTP.
- Rate limit хранится в памяти процесса. Несколько инстансов не делят счётчик; для кластера нужен Redis.
- `AUTH_DEV_MAILBOX=true` в настоящем production откроет `/dev/mailbox`. В проде флаг должен быть выключен, а письма идут только через HTTP-адаптер.
- In-memory rate limit и health не заменяют WAF, backup и мониторинг инцидентов.

## Секреты

Не коммитить `.env`. В репозитории только `.env.example` с заглушками. Страницы и JSON админки не должны содержать `AUTH_SECRET`, пароль БД, `sk-`, `whsec_`, `Bearer` и ключи провайдеров. Проверка: `npm test` и `npm run test:e2e`.
